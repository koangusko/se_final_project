# 完整檢查

1. 執行 `pnpm format`，再執行 `pnpm verify`。
2. 有錯誤時逐一修正後重跑，直到全部通過。修正原則：
   - 型別錯誤：修程式，不要用 `as any`、`@ts-ignore`、`!` 蓋掉。
   - lint 錯誤：修程式；真的需要例外時用 `// oxlint-disable-next-line <規則> -- <理由>`，並在回報中列出。
   - 模組邊界違規：改成透過 API、`core/` 或資料表取得資料，不要直接 import 別的模組。
   - 測試失敗：先判斷是程式錯還是測試錯；不要為了通過而改測試的預期結果或名稱。
3. 檢查 `git status`，確認沒有誤加的檔案（`.data/`、`.env`、暫存檔）。
4. 回報檢查結果與修了什麼。
